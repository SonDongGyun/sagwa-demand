# 사과 요구서 · 진정성 심사원 🍎

> 말로만 하는 사과는 접수되지 않습니다.

상대방에게 **정식으로 사과를 요구**하고, 상대는 **3단계 진정성 심사**를 통과해야 사과가 접수되는
한 장짜리 웹 페이지입니다. 빌드 도구는 없습니다. `index.html` 을 열면 그대로 굴러갑니다.

서버(Supabase)를 붙이면 링크가 짧아지고, 내 사건철이 생기고, 수리증의 단서 조항이
실제로 집행됩니다. **안 붙여도 전부 동작합니다** — 없으면 있던 대로 URL 에 다 싣습니다.

## 어떻게 굴러가나

```
[나]  요구서 작성 ──링크──▶ [상대] 요구서 열람 ─▶ 심사 1·2·3 ─▶ 판정서
                                                                  │
[나]  결과 수령 ─▶ 도장 찍기 ─▶ 사과 수리증 ◀────────링크─────────┘
        │
        ├──링크──▶ [상대] 수리증 수령 (화면에 사과비가 내린다)
        │
        └─ 내 사건철 ─▶ 또 그러면 ─▶ 효력 상실 (양쪽 화면에 붉은 띠가 찍힌다)
```

**링크에 무엇이 실리나** — 두 가지 모드가 있고, 문법은 같습니다.

| | 서버 없음 (기본) | 서버 있음 |
|---|---|---|
| `?d=` `?r=` `?a=` 값 | base64url JSON 통째로 | 사건번호 8자 (`ba4ptww9`) |
| 링크 길이 | 300~600자 | 40자 남짓 |
| 저장 위치 | 아무 데도 안 남음 | Supabase, 90일 뒤 자동 삭제 |
| 사건철 · 재발 신고 | 없음 | 있음 |

`boot()` 는 값이 8자 코드면 서버에 묻고, 아니면 그 자리에서 디코드합니다.
그래서 **예전에 보낸 긴 링크는 계속 열립니다.**

## 인터랙션

**요구서 작성** — 청구인·피청구인·사건의 요지를 적고, 요구 조건 8종 중 원하는 것을 고릅니다.
**분노 게이지(1–10)** 는 그대로 심사 난이도가 됩니다. 화가 많이 났을수록 상대가 고생합니다.

**도망가는 버튼** — 요구서 하단의 `미안한데 내가 왜?` 버튼은 커서가 닿으면 도망칩니다.
6번 도망친 뒤에야 잡히고, 도주 시도 1회당 진정성 **-2점**(최대 -12점)이 판정서에 그대로 기록됩니다.

## 심사 3종

| 심사 | 내용 | 조작 | 반영 |
|---|---|---|---|
| 1. 정중히 고개 숙이기 | 허리 각도를 초록 구간(78°–92°)에 **3초** 유지. 몸이 흔들리고, 110°를 넘기면 이마를 찧습니다 | `Space` 또는 버튼을 누르고 있기 | 30% |
| 2. 사과문 받아쓰기 | 자동 생성된 사과문을 그대로 입력(제한 150초). 띄어쓰기·문장부호는 봐줍니다. 붙여넣기는 오타 +3 | 키보드 | 30% |
| 3. 사과 줍기 | 떨어지는 사과🍎를 받고 **변명**과 **돌**은 피합니다. **사과 100점**을 모으면 그 자리에서 통과. 제한 30초, 마음 3개 | 마우스 · 화면 드래그 · `←` `→` | 40% |

세 점수의 가중 평균에서 도주 감점을 뺀 값이 **진정성 지수**이고, 등급이 매겨집니다.

| 지수 | 등급 | 판정 |
|---|---|---|
| 92+ | **S** | 전면 수용 |
| 80+ | **A** | 수용 |
| 65+ | **B** | 조건부 수용 |
| 45+ | **C** | 재심 권고 |
| 0+ | **F** | 기각 |

판정서는 도장이 찍힌 문서로 나오고, `인쇄 / PDF 저장` 으로 남길 수 있습니다.
결과 링크를 청구인에게 보내면 `사과를 받아들인다` / `재심 요구` 를 고르는 화면이 뜹니다.

## 사과 수리 — 받아들이는 쪽의 절차

받아들이는 것도 버튼 한 번으로는 안 됩니다.

**도장 찍기** — 덧붙일 말을 한 줄 적고(생략 가능), 도장을 **1.2초 동안 끝까지 누르고 있어야** 합니다.
중간에 손을 떼면 도장이 튀어 올라가고 몇 %에서 놨는지 말해 줍니다. 덜 찍힌 도장은 효력이 없습니다.
`아직 마음이 안 풀렸습니다` 로 언제든 빠져나갈 수 있습니다 — 강제로 용서시키지 않습니다.

**사과 수리증** — 다 찍으면 수리번호가 붙은 증서가 발급됩니다. 청구인 이름이 새겨진 붉은 도장,
심사 등급과 진정성 점수, 덧붙인 한마디, 그리고 단서 조항이 들어갑니다 —
*본 수리증은 동일 사건이 재발할 경우 즉시 효력을 잃습니다.*

수리증 링크(`?a=`)를 사과한 사람에게 보내면, 그쪽 화면에서 수리증이 열리며 **사과비가 내립니다**.
`인쇄 / PDF 저장` 으로 남길 수 있고, 이걸로 그 건은 종결입니다.

## 내 사건철과 재발 신고 (서버 있을 때)

작성 화면의 `내 사건철 열기` 로 들어갑니다 — 서버가 붙어 있고 발부한 건이 있을 때만 보입니다.

**사건철** — 이 기기에서 발부한 요구서가 상태와 함께 쌓입니다. `심사 대기` · `판정 완료` ·
`수리됨` · `효력 상실` 네 가지. 각 건은 바로 열거나 링크를 다시 복사할 수 있습니다.

로그인은 없습니다. 첫 방문 때 만든 UUID 하나(`localStorage` 의 `sagwa.keeper`)를
헤더로 보내고 서버는 그 **해시만** 저장합니다. 기기를 바꾸면 사건철도 사라집니다 —
계정을 만들지 않기로 한 대가이고, 그래서 개인정보를 받지 않습니다.

**재발 신고** — 수리증에 적힌 *동일 사건이 재발할 경우 즉시 효력을 잃습니다* 를
문구로만 두지 않습니다. 사건철에서 `이 사건이 또 일어났습니다` 를 누르고
무슨 일이었는지 한 줄 적으면(생략 가능) 그 수리증에 붉은 **효력 상실** 띠가 찍히고,
적은 이유가 띠 옆에 그대로 남습니다. 상대가 가진 `?a=` 링크에서도 똑같이 보입니다.
발부한 본인(키퍼 대조)만 누를 수 있습니다.

## 실행

```bash
git clone https://github.com/SonDongGyun/sagwa-demand.git
cd sagwa-demand
python3 -m http.server 8931      # 또는 그냥 index.html 을 브라우저로 열기
```

`file://` 로 열어도 동작합니다(ES 모듈 대신 일반 스크립트를 쓴 이유입니다).
다만 클립보드 복사는 보안 컨텍스트가 아니면 `execCommand` 폴백으로 넘어갑니다.

**서버까지 켜고 보려면** — 진짜 Supabase 없이 `/api` 를 흉내 내는 서버가 들어 있습니다.

```bash
node tools/devserver.mjs 8931    # 정적 + /api/*, 메모리 DB
```

`curl localhost:8931/api/health` 가 `{"ok":true,"db":true}` 면 켜진 겁니다.
데이터는 프로세스 안에만 있고 끄면 사라집니다.

**배포** — Vercel 로 올리면 `/api/*.mjs` 가 그대로 서버리스 함수가 됩니다.
환경변수 두 개와 SQL 한 벌이 필요합니다 → **[docs/DEPLOY.md](docs/DEPLOY.md)**

**GitHub Pages** — 정적 파일만 올라가므로 화면은 다 뜨지만 `/api` 는 없습니다.
짧은 링크·사건철·재발 신고 없이 URL 토큰 모드로만 굴러갑니다.

## 구조

```
index.html          화면 12개(작성·발부·조회중·열람·심사3·판정·수령·날인·수리증·사건철)의 정적 마크업
styles.css          공문서 + 붉은 도장 톤. 변수 기반, 다크 배경 / 크림 종이
js/share.js         base64url 인코딩, 공유 링크 생성, 클립보드(폴백 포함)
js/games.js         심사 3종. 각각 start() → Promise<{score:0~100, detail}>
js/store.js         /api 래퍼. 어떤 실패든 null 로 떨어져 URL 토큰 모드로 폴백
js/app.js           화면 전환, 요구서 작성/열람, 심사 진행, 판정, 사과 수리, 사건철

api/_db.mjs         PostgREST 호출·사건번호 생성·키퍼 해시·env 없으면 501 (라우트 아님)
api/health.mjs      GET  → {ok, db}      서버가 켜져 있는지 한 번 묻는 곳
api/case.mjs        POST 요구서 접수 / GET ?c=CODE 사건 조회
api/verdict.mjs     POST 심사 결과 기록
api/settle.mjs      POST 사과 수리(도장). 같은 건에 두 번 찍어도 한 번으로 친다
api/void.mjs        POST 재발 신고 → 효력 상실. 발부자만 (키퍼 불일치 403)
api/casefile.mjs    GET  이 기기가 발부한 사건 목록

docs/schema.sql     테이블 3개 + RLS + 90일 만료 청소 함수
tools/devserver.mjs 로컬용. 정적 파일 + /api 동적 import (Vercel 흉내)
tools/mock-supabase.mjs  PostgREST 를 필요한 만큼만 흉내 내는 메모리 DB
```

**의존성 0개, 빌드 0단계** — 서버가 붙은 뒤에도 그대로입니다.
`supabase-js` 대신 PostgREST 를 `fetch` 로 직접 부릅니다. `package.json` 이 없습니다.

## 개발 메모

- `?debug=1` 을 붙이면 사과 줍기 게임 중 `window.__catchState()` 로 아이템·바구니·점수를 들여다볼 수 있습니다.
- **정적 서버 캐시** — `python3 -m http.server` 는 `Cache-Control` 을 보내지 않아 브라우저가 옛 JS 를
  그대로 물고 있습니다. `styles.css?v=8`, `js/*.js?v=8` 처럼 쿼리를 붙여 두었으니 고칠 때마다 올립니다.
- 사과문의 조사는 받침을 보고 `은/는` 을 고릅니다(`민수는`, `동균은`).
- **받아쓰기와 한글 IME** — 한글은 `ㅈ → 저` 로 조합되며 들어옵니다. 조합 중인 마지막 글자는
  채점·색칠에서 빼고 `compositionend` 이후에만 확정으로 셉니다. 그러지 않으면 정상 입력이 전부 오타가 됩니다.
- **받아쓰기 완료 판정** — 두 단계로 봅니다. ① 꼬리 공백·겹공백·스마트 따옴표를 정규화한 비교,
  ② 그래도 안 맞으면 띄어쓰기와 문장부호를 전부 뺀 비교. 글자만 맞으면 통과입니다.
  사과의 진정성은 쉼표 위치에 있지 않습니다. 문장에는 키보드로 칠 수 없는 문자(`…` 등)를 절대 넣지 않습니다.
- **받아쓰기에서 갇히지 않게** — 틀리면 *몇 번째 글자가 무엇이어야 하는지*를 그때그때 알려주고,
  90% 이상 적으면 `다 적었습니다 · 제출` 버튼이, 15초가 지나면 탈출 버튼이 나옵니다.
  제출 버튼은 틀린 글자를 대신 선택해 줍니다. 다 옮겨 적었으면 점수는 45점 아래로 내려가지 않습니다.
- **사과 줍기 목표** — 사과 **100점**을 모으면 그 자리에서 끝납니다. 진정성 점수는 `모은 점수 / 100`.
  시간이 다 되거나 마음이 닳으면 모은 만큼만 인정합니다.
- **색은 [Radix Colors](https://www.radix-ui.com/colors) 의 12단계 구성을 따랐습니다** —
  1~2 배경, 3~5 컴포넌트 면, 6~8 경계선, 9~10 솔리드 강조, 11~12 글자.
  강조색은 채도가 가장 높은 9단계(`#e5484d`)를 씁니다. 표시용 서체는 Pretendard 한 벌로 통일했고,
  고정폭 서체엔 한글 글리프가 없어 `--mono` 뒤에 한글 폰트를 붙여 두부 네모를 막았습니다.
- **도장은 좌표를 재서 내려갑니다** — 도장이 얼마나 내려가야 인주 자리에 닿는지는
  화면이 보인 뒤 `getBoundingClientRect()` 로 계산합니다. 하드코딩한 px 는 480px 과 390px 에서 서로 어긋납니다.
- **URL 토큰 3종** — `?d=` 요구서, `?r=` 심사 결과, `?a=` 사과 수리증. `boot()` 는 `a → r → d` 순으로 봅니다.
  깨진 토큰은 전부 `null` 로 떨어져 작성 화면으로 폴백합니다.
- **서버는 거들 뿐** — `Store` 의 모든 메서드는 실패하면 예외를 던지지 않고 `null` 을 돌려줍니다.
  env 가 없으면 `/api/*` 는 501 `{reason:'not-configured'}` 을 주고, 클라이언트는 조용히
  URL 토큰 모드로 갑니다. **서버가 죽어도 앱은 안 죽습니다.** 켜고 끄며 양쪽을 다 확인하세요.
- **env 는 콜드 스타트에 한 번만 읽습니다** — `_db.mjs` 가 모듈 로드 시점에 읽으므로,
  Vercel 에서 환경변수를 바꿨으면 **재배포해야** 반영됩니다. 로컬 테스트에서도
  같은 프로세스로는 못 바꿉니다(별도 프로세스로 띄워야 함).
- **사건번호 8자** — `23456789abcdefghjkmnpqrstuvwxyz` 31자에서 뽑습니다. `0/O`, `1/l` 을 뺀 건
  전화로 불러 줄 일이 있어서입니다. 31^8 ≈ 8.5×10^11. 충돌하면 4번까지 다시 뽑습니다.
- **RLS 는 정책 없이 켭니다** — 브라우저는 Supabase 를 직접 부르지 않습니다. `anon` 키를
  아예 클라이언트에 내려보내지 않고, 서버 라우트가 `service_role` 로만 붙습니다.
  정책을 하나도 안 만든 채 RLS 를 켜 두면 그 외 경로는 전부 막힙니다.
- **사건철 키는 해시만 저장합니다** — 헤더 `x-sagwa-keeper` 로 UUID 를 받고 `sha256` 해서 넣습니다.
  DB 가 통째로 새도 어느 기기 것인지 되짚을 수 없습니다.
- **`expires_at=gt.now`** — PostgREST 필터의 `now` 는 문자열이고 Postgres 가 시각으로 파싱합니다.
  `now()` 라고 쓰면 함수 호출로 보고 실패합니다.
- 사용자 입력은 전부 `textContent` 로만 넣습니다. 링크에 담긴 JSON도 마찬가지입니다.
- 최고 기록은 `localStorage` 의 `sagwa.best` 하나만 씁니다.
- 헤드리스 크로미움으로 전체 흐름(작성 → 링크 → 심사 3종 → 판정 → 결과 수령 → 도장 → 수리증 →
  수리증 링크 재열람 → 모바일 390px → 깨진 토큰 폴백)을 확인했습니다.
  서버 모드는 브라우저 컨텍스트 두 개(발부자 / 사과한 사람)를 띄워 짧은 링크 · 사건철 ·
  재발 신고 · 없는 사건번호까지 별도로 확인했습니다.
